# 放送視聴データ活用ハンズオン

非特定視聴データを題材に、データの取り込みからデータ変換、セマンティックレイヤー、AI エージェント、可視化アプリまでを Snowflake の中だけで一本通すハンズオン教材です。所要時間は約 2 時間で、Snowsight のブラウザ画面だけで完結します。ローカルへのツールのインストールやコマンドライン操作は必要ありません。

対象は**地上波 5 局の非特定視聴データだけ**です。配信（見逃し）のデータは含めていません。理由は[こちら](#地上波だけを対象にしている理由)に書いています。

## このハンズオンで体験できること

- 5 つの放送局から届いたログを 1 か所に集め、局をまたいだチャンネル遷移を復元する
- 3 階層の ID（各局 ID、共通 ID、IP アドレス）を名寄せし、同じデータから粒度の違う数字を出し分ける
- dbt でクレンジングから指標算出までのパイプラインを組み、依存関係を図で確認する
- 視聴区間（from-to）のデータを 1 分単位に分解したときに、データ量がどれだけ増えるかを実測する
- リーチ、フリークエンシー、インプレッションの関係を、同じ定義から出す
- 指標の定義を Snowflake 側に持たせ、自然言語で分析できる状態にする
- 番組やコマーシャルの説明文を検索できるようにし、数値の集計と組み合わせて回答させる
- マート層をそのまま可視化アプリにする
- 生データと集計データでアクセス権を分け、識別子に伏せ字をかける

## 前提条件

- Snowflake アカウント（トライアルで実施できます）
- ACCOUNTADMIN ロール
- Cortex が利用できるリージョン（AWS 東京リージョンで確認済み）

教材のリポジトリは公開してあるので、GitHub のアカウントや個人アクセストークンの準備は必要ありません。

## 進め方

**コピーと貼り付けは第 0 章だけです。**

第 0 章で、教材のリポジトリを Snowsight のワークスペースに取り込みます。以降の章は、左側のファイル一覧から `sql/stepN_*.sql` を開いて実行するだけです。dbt のモデルもアプリのコードも、同じワークスペースの中にあります。

```
第 0 章  ワークシートに step0_check.sql を貼って実行（ここだけコピペ）
           ↓  API 統合ができる
         ワークスペースを作る（画面操作）
           ↓  リポジトリの中身が全部そろう
第 1 章  ワークスペースで sql/step1_setup.sql を開いて実行
第 2 章  ワークスペースで dbt/ を動かす
第 3 章  ワークスペースで sql/step3_semantic.sql を開いて実行
第 4 章  ワークスペースで sql/step4_agent.sql を開いて実行
第 5 章  ワークスペースで sql/step5_app.sql を開いて実行
第 6 章  ワークスペースで sql/step6_rbac.sql を開いて実行
```

第 0 章でワークスペースを作るのは、そこから先で使うファイルをすべて手元に置くためです。Git リポジトリを参照する `API INTEGRATION` はアカウントに属するオブジェクトなので、データベースを作る前に用意できます。

データの構造とカラムの意味は [docs/data_dictionary.md](docs/data_dictionary.md) にまとめています。

| 種別 | 名前 |

| スキーマ | `RAW` / `STG` / `INT` / `MART` / `INTEGRATIONS` |

## サンプルデータの規模

| データ | 行数 |
|---|---|
| 視聴区間（5 局分の合計） | 1,050,648 |
| コマーシャルの放送実績 | 750 |
| 番組の放送枠 | 790 |
| 番組マスタ / コマーシャルマスタ / 局マスタ | 60 / 20 / 5 |
| パネル調査で属性が判明している端末 | 2,000（全体の 10 パーセント） |

対象期間は 2026 年 5 月 1 日から 7 月 31 日までの 92 日間、3 ヶ月分です。月をまたいで積み上がるデータを見てもらうため、視聴は期間の後半にかけてゆるやかに減るようにしてあります。番組は 3 ヶ月間同じ曜日・同じ時刻に放送されますが（同一クールのため）、**コマーシャルには 2 週間から 4 週間の出稿期間があります**。すべて架空のデータで、実在の放送局や番組、広告主とは関係ありません。

## 地上波だけを対象にしている理由

放送と配信を足して「配信を加えるとリーチがどれだけ広がるか」を出すには、テレビの受信機のログと配信のログを**同じ相手だと言える状態**で突き合わせる必要があります。しかし両方とも非特定のデータであり、その名寄せをどう作るか自体が最大の論点になります。

この教材では、名寄せが済んでいる前提のデータを作って見せることはしません。代わりに、**5 局の放送データを集めたことで初めて出る数字**に絞っています。局をまたいだチャンネル移動がその代表例で、これは 1 局のデータだけでは絶対に出ません。

なお、放送のコマーシャル接触は**推定値**です。視聴区間にスポットの放送時刻が入っていたかどうかで判定しているため、席を外していても接触として数えます。エージェントも、接触の数字を返すときにこの断り書きを添えます。
