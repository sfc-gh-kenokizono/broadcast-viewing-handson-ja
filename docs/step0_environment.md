# 第 0 章 環境の確認

所要時間の目安 5 分

## 目的

これから 2 時間、同じ 1 つの環境で作業を進めます。最初にどのアカウントを使うかを確定させておくと、途中で「作ったはずのものが見つからない」という迷子になりません。

## 事前に用意しておくもの

| 項目 | 内容 |
|---|---|
| Snowflake アカウント | トライアルで実施できます。Cortex が利用できるリージョンであることを確認してください（AWS 東京リージョンで確認済み） |
| ロール | ACCOUNTADMIN |

教材のリポジトリは公開してあるので、**GitHub のアカウントやトークンの準備は必要ありません**。

## 使うファイル

[sql/step0_check.sql](../sql/step0_check.sql)

Snowsight でワークシートを新規作成し、このファイルの内容を貼り付けてから、上から順に実行していきます。書き換えは必要ありません。

以降の章も同じ進め方です。各章に対応する SQL ファイルが `sql/` にあります。

## 1. どのアカウントで実施するかを決める

Snowsight にサインインし、画面左下のアカウント名を確認します。複数のアカウントをお持ちの場合は、ここで 1 つに決めてしまってください。以降のすべての作業をそのアカウントで行います。

SQL でも確認できます。

```sql
SELECT
  CURRENT_ACCOUNT()  AS "アカウント",
  CURRENT_REGION()   AS "リージョン",
  CURRENT_USER()     AS "ユーザー",
  CURRENT_ROLE()     AS "ロール",
  CURRENT_VERSION()  AS "バージョン";
```

ロールが `ACCOUNTADMIN` でない場合は、ワークシート右上のロール切り替えから変更してください。

### 日本語の列名はダブルクォートで囲みます

上のクエリで `"アカウント"` のように囲んでいるのは、そうしないと Snowflake が識別子として解釈できず、次のエラーになるためです。

```
syntax error line 2 at position 21 unexpected 'アカウント'.
```

英数字とアンダースコアだけの名前は囲まなくても通りますが、日本語・空白・記号を含む場合は囲む必要があります。この教材の SQL では、結果を読みやすくするために日本語の列名を多く使っているので、囲む書き方で統一してあります。

## 2. 使うウェアハウスを選ぶ

`SELECT` で計算をするには、ウェアハウス（計算資源）が選ばれている必要があります。選ばれていないと次のエラーになります。

```
No active warehouse selected in the current session.
```

このハンズオン用のウェアハウスは第 1 章で作ります。第 0 章の時点では、トライアルに最初から用意されているものを使います。

```sql
SHOW WAREHOUSES;

USE WAREHOUSE COMPUTE_WH;
```

一覧に `COMPUTE_WH` がない場合は、出てきた名前に読み替えてください。

## 3. Cortex が使えることを確認する

### 先にクロスリージョンを有効にします

モデルは提供されているリージョンが限られます。自分のアカウントのリージョンにないモデルを呼ぶと、Cortex は「使えません」と返すだけで、勝手に他のリージョンへは出ていきません。次の設定を入れると、足りないモデルを他のリージョンで処理します。

```sql
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';
```

このハンズオンはトライアルでの検証を前提にしているため、**あとで詰まらないよう最初から有効にします**。

本番環境では、データが処理されるリージョンが変わることになります。データの置き場所に関する規程を確認したうえで判断してください。値には `'ANY_REGION'` のほかに、許可するリージョンを絞って `'AWS_US'` のように指定することもできます。既定値は `DISABLED` です。

```sql
SELECT AI_COMPLETE(
  'claude-sonnet-4-5',
  '一言で自己紹介してください'
) AS "応答";
```

文章が返ってくれば、第 3 章以降で使う機能が利用できます。

設定が入っているかは次で確認できます。

```sql
SHOW PARAMETERS LIKE 'CORTEX_ENABLED_CROSS_REGION' IN ACCOUNT;
```

## 4. 教材を取り込むための扉を開ける

ここから先の章では、教材のファイル（SQL、dbt のモデル、アプリのコード）を Snowsight のワークスペースに取り込んで、**そこから直接実行**していきます。コピーと貼り付けはこの第 0 章だけで終わりです。

そのために必要なのが **API 統合**です。

```sql
CREATE API INTEGRATION IF NOT EXISTS BCAST_GIT_API
  API_PROVIDER = git_https_api
  API_ALLOWED_PREFIXES = ('https://github.com/sfc-gh-kenokizono')
  ENABLED = TRUE;

SHOW INTEGRATIONS LIKE 'BCAST_GIT_API';
```

1 行返ってくれば準備完了です。

### API 統合は何をするものか

「**このアカウントから外に出ていってよい先**」を宣言するオブジェクトです。`API_ALLOWED_PREFIXES` に書いていないドメインには接続できません。外部との通信を管理者が宣言した先に限定できる、というのがこの仕組みの意図です。

アカウントに属するオブジェクトなので、データベースは要りません。だから第 1 章でデータベースを作る前に、ここで作れます。

`IF NOT EXISTS` を付けているので、あとで第 1 章を実行しても作り直されません。作り直しても接続が壊れないことは確認していますが、余計な変更をしないほうが安全です。

このリポジトリは公開しているので、認証情報は必要ありません。非公開リポジトリを使う場合の手順は `sql/step1_setup.sql` の末尾にあります。

## 5. ワークスペースを作る

ここは SQL ではなく画面での操作です。

1. 左メニューで **Projects » Workspaces** を開きます
2. **ワークスペースのメニュー**（左上のワークスペース名の横。初回は `+ Add New`）から **From Git repository** を選びます
3. 次のように入力します

| 項目 | 値 |
|---|---|
| Repository URL | `https://github.com/sfc-gh-kenokizono/broadcast-viewing-handson-ja.git` |
| ワークスペース名 | `bcast_viewing` |
| API Integration | `BCAST_GIT_API` |
| 認証方法 | **Public repository** |

4. **Create** を選びます

左側にリポジトリの中身が表示されます。**以降の章では、ここからファイルを開いて実行していきます。**

> **⚠️ 「dbt プロジェクト」ボタンは押さないでください**
>
> 初期画面に SQL ファイル、ノートブック、**dbt プロジェクト**、Streamlit アプリなどのボタンが並んでいます。ここの「dbt プロジェクト」は空のプロジェクトを新規作成するもので、教材は入ってきません。

### 認証方法の選択肢

| 選択肢 | 使う場面 |
|---|---|
| OAuth2 | GitHub と連携して認証する。書き込みもしたい場合 |
| Personal access token | 非公開リポジトリを、トークンを保存したシークレットで参照する場合 |
| **Public repository** | 公開リポジトリ。認証情報は不要 ← **今回はこれ** |

`Public repository` を選んだ場合、ワークスペースからリポジトリへの**コミットとプッシュはできません**。教材を読んで実行するだけなので問題ありません。手元で書き換えて保存することはできます。

### ワークスペースは何の上に作られるのか

事前の有効化は必要ありません。初めてワークスペースを開いたときに、そのユーザー専用の**個人データベース**が自動で作られます。

| 項目 | 内容 |
|---|---|
| 作られるタイミング | ユーザーが初めてワークスペースを開いたとき（自動） |
| 名前 | `USER$<ユーザー名>` |
| 中に置けるもの | ワークスペース、Git リポジトリ、シークレット、スキーマなど |
| 中に置けないもの | テーブルやビューなどの通常のデータオブジェクト |
| 権限 | 実行時の権限はそのユーザーが持っているロールのまま。**新しいデータアクセスは増えない** |

最後の行が実務では重要です。「個人用のデータベースができる」と聞くと管理面を心配されますが、見えるデータが増えるわけではありません。

## 6. 使う容量の目安

このハンズオンで扱うデータは圧縮後で 20 メガバイト程度、Snowflake 上に展開しても数百メガバイトです。ウェアハウスは XSMALL を使い、いちばん重い処理でも 1 分程度で終わります。トライアルの残り容量を大きく消費することはありません。

各章の終わりに、その章で使った時間とクレジットを確認するクエリを載せています。実際の規模で見積もりを立てるときの手がかりになります。

- `AI_COMPLETE` の呼び出しが文章を返す

- ワークスペースの左側に `app` `data` `dbt` `docs` `sql` などのフォルダが並んでいる
