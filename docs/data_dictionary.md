# データ辞書

このハンズオンで扱うデータの構造です。放送の非特定視聴データが持つ特徴をそのまま小さく再現しています。

## 1. 視聴区間データの粒度

視聴ログの 1 行は「1 台の受信機が、あるチャンネルを、いつからいつまで見ていたか」を表します。常時ビーコンを送っているのではなく、チャンネルを合わせた瞬間と離れた瞬間が 1 レコードになります。この形を from-to 形式と呼びます。

```
COMMON_ID=C000123  CHANNEL_CODE=041  VIEW_FROM=2026-07-05 20:00:00  VIEW_TO=2026-07-05 20:12:00
```

## 2. RAW スキーマのテーブル

### VIEWING_LOG_NW01 から VIEWING_LOG_NW05

各局から届く非特定視聴データです。局ごとに別のテーブルとして受け取ります。

| カラム | 型 | 論理名 | 説明 |
|---|---|---|---|
| `NETWORK_ID` | VARCHAR(4) | 放送ネットワークの ID | 放送局を特定する ID |
| `STATION_DEVICE_ID` | VARCHAR(24) | デバイス ID（各局 ID） | 各局が受信機に個別に付与する ID。**局をまたいで一致しません** |
| `COMMON_ID` | VARCHAR(12) | 共通 ID | 5 局横断の非特定リンクキー。受信機 1 台に 1 つ |
| `IP_ADDRESS` | VARCHAR(15) | IP アドレス | 契約世帯の回線ごとに割り当てられる識別子。外部データとの突合に使う |
| `POSTAL_CODE` | VARCHAR(8) | 郵便番号 | 視聴エリアの特定に使う |
| `CHANNEL_CODE` | VARCHAR(3) | 視聴チャンネル | どのチャンネルを視聴したか |
| `VIEW_FROM` | TIMESTAMP_NTZ | 視聴時間（from） | 視聴の開始時刻 |
| `VIEW_TO` | TIMESTAMP_NTZ | 視聴時間（to） | 視聴の終了時刻 |

このデータに含まれないものが 3 つあります。ハンズオンの設計上、重要な前提です。

- 世帯構成（何人家族か）は分かりません
- 個人の属性（性別・年齢）は分かりません
- **他局を見ていた時間は分かりません**。各局は自局が見られている間のログしか取得できません

3 つめが、5 局分を 1 か所に集める理由です。1 台の受信機のチャンネル遷移は、5 局のログを共通 ID で束ねて初めて見えるようになります。

### NETWORK_MASTER

| カラム | 型 | 説明 |
|---|---|---|
| `NETWORK_ID` | VARCHAR(4) | 局の ID（`NW01` から `NW05`） |
| `NETWORK_NAME` | VARCHAR(40) | 局の表示名 |
| `CHANNEL_CODE` | VARCHAR(3) | その局のチャンネル番号 |

### PROGRAM_MASTER

番組のマスタです。`SYNOPSIS` に日本語の番組概要文を持っており、検索サービスの対象になります。

| カラム | 型 | 説明 |
|---|---|---|
| `PROGRAM_ID` | VARCHAR(8) | 番組 ID |
| `PROGRAM_NAME` | VARCHAR(60) | 番組名 |
| `NETWORK_ID` | VARCHAR(4) | 放送する局 |
| `GENRE` | VARCHAR(20) | ドラマ、バラエティ、アニメ、ニュース、スポーツ、音楽、映画、情報 |
| `TIME_SLOT` | VARCHAR(20) | 朝、昼、夕方、ゴールデン、深夜 |
| `DURATION_MIN` | NUMBER(4,0) | 放送時間（分） |
| `SYNOPSIS` | VARCHAR(400) | 番組の概要文 |

### PROGRAM_SCHEDULE

番組の放送枠です。各局について毎日 4:00 から 24:00 までの 20 時間を切れ目なく編成し、1 局 1 日あたり平均 19 枠あります。同じ番組が期間中に複数回放送されます。視聴区間がどの番組の時間帯に重なっていたかは、このテーブルと時刻の範囲で結合して判定します。視聴ログ側に番組 ID は入っていません。

| カラム | 型 | 説明 |
|---|---|---|
| `PROGRAM_ID` | VARCHAR(8) | 番組 ID |
| `NETWORK_ID` | VARCHAR(4) | 局の ID |
| `AIR_DATE` | DATE | 放送日 |
| `AIR_FROM` | TIMESTAMP_NTZ | 放送開始時刻 |
| `AIR_TO` | TIMESTAMP_NTZ | 放送終了時刻 |

### CM_MASTER

局全体で放送されるコマーシャル**素材**のマスタです。1 行が 1 種類の素材で、100 素材を収録しています。`CREATIVE_DESC` が検索サービスの対象になります。

100 素材のうち、`IS_ANALYSIS_TARGET = TRUE` の 20 素材が、このハンズオンで接触を分析する対象です。この 20 素材には 2 週間から 4 週間の出稿期間があります。残り 80 素材は、局全体の CM ブレークを現実的な密度にするための背景素材です。

| カラム | 型 | 説明 |
|---|---|---|
| `CM_ID` | VARCHAR(8) | コマーシャル ID |
| `ADVERTISER` | VARCHAR(40) | 広告主（架空） |
| `CATEGORY` | VARCHAR(20) | 業種のカテゴリ |
| `DURATION_SEC` | NUMBER(4,0) | 秒数 |
| `CREATIVE_DESC` | VARCHAR(400) | 素材の内容の説明文 |
| `CAMPAIGN_FROM` | DATE | 出稿期間の開始日 |
| `CAMPAIGN_TO` | DATE | 出稿期間の終了日 |
| `IS_ANALYSIS_TARGET` | BOOLEAN | ハンズオンで接触分析する 20 素材なら TRUE |

### CM_SPOT

局全体でコマーシャルが実際に放送された実績です。**1 行は、1 つの CM 素材が 1 回放送されたこと**を表します。各局は 4:00〜24:00 に、およそ 20 分ごと・3 分間の CM ブレークを持ちます。期間全体で 303,600 回、1 局 1 日あたり 660 回の放送実績があります。

`CM_MASTER` が「何を放送するか」のマスタ、`CM_SPOT` が「いつ・どの局で放送したか」のトランザクションです。接触分析では、`CM_MASTER.IS_ANALYSIS_TARGET = TRUE` の20素材に絞ります。

**これは推定です。** 「誰がコマーシャルを見たか」というログはどこにも存在しないため、視聴していた時間帯にスポットが流れていたかどうかで判定しています。席を外していても接触として数えます。

| カラム | 型 | 説明 |
|---|---|---|
| `SPOT_ID` | VARCHAR(12) | 放送実績の ID |
| `CM_ID` | VARCHAR(8) | コマーシャル ID |
| `NETWORK_ID` | VARCHAR(4) | 放送した局 |
| `AIR_AT` | TIMESTAMP_NTZ | 放送時刻 |

### PANEL_DEMOGRAPHICS

パネル調査によって属性が判明している端末です。全体の 10 パーセントだけに値があります。残りの 90 パーセントは属性が分かりません。

| カラム | 型 | 説明 |
|---|---|---|
| `COMMON_ID` | VARCHAR(12) | 共通 ID |
| `GENDER_AGE_SEGMENT` | VARCHAR(4) | `T`（13 から 19 歳） / `F1` `F2` `F3` / `M1` `M2` `M3` |
| `SURVEY_DATE` | DATE | 調査日 |

## 3. ID の階層

4 つの識別子が登場し、それぞれ役割が異なります。

| 識別子 | 粒度 | 有効な範囲 | 使いどころ |
|---|---|---|---|
| デバイス ID（各局 ID） | 受信機 1 台 | **その局の中だけ** | 局内でのデバイスの識別 |
| 共通 ID | 受信機 1 台 | 5 局横断 | 局をまたいだ名寄せ、チャンネル遷移の復元 |
| IP アドレス | 世帯（回線） | 外部にも共有できる | 外部データとの突合 |
| 放送ネットワークの ID | 局 | — | 局の識別 |

同じ生データから、集計の単位を変えると 3 通りの数字が出ます。ハンズオンの第 2 章で確認します。

```
IP アドレス   192.0.2.45
  ├── 共通 ID  C000123  ── 各局 ID  NW01-D-8f2a1c / NW02-D-004512 / NW04-D-77e903
  └── 共通 ID  C000988  ── 各局 ID  NW01-D-1b90ff / NW03-D-220145
```

このハンズオンでは、複数の共通 ID が同じ IP アドレスを共有するケースを意図的に含めています。集合住宅で同じ回線を複数世帯が使う状況に相当し、IP アドレスを世帯の代わりに使うことの限界がそのまま現れます。

## 4. 意図的に含めている異常値

生データのままだと使えないことを確認するため、RAW に以下を混ぜています。第 2 章のクレンジングで除外します。

| 内容 | 件数 |
|---|---|
| 終了時刻が開始時刻より前 | 200 |
| 視聴時間が 24 時間を超える | 148 |
| 完全に重複した行 | 300 |
| `NW03` の 2026 年 7 月 17 日のログが欠落 | 1 日分 |

## 5. 1 分単位への分解について

視聴区間のデータは、事実を変えずに粒度だけ上げることができます。

```
分解前（1 行）
  C000123  041  20:00 から 20:12

分解後（12 行）
  C000123  041  20:00
  C000123  041  20:01
  ...
  C000123  041  20:11
```

毎分の視聴人数のような指標は、分の側から数えられる形にしておくと素直に集計できます。一方で、平均の視聴区間長を M 分とすると行数はおよそ M 倍になります。このハンズオンのデータでは、105 万行が約 1,212 万行になります。

増えるのは変換後の層だけで、受け取る生データの量は変わりません。第 2 章で実際に行数を数えて確認します。

## 6. 各層の役割

| 層 | 役割 | 内容 |
|---|---|---|
| `RAW` | 原本の保全 | 受け取ったまま。加工しない |
| `STG` | クレンジング | 異常値の除外、型変換、視聴日の付与 |
| `INT` | 中間処理 | ID の名寄せ、番組枠との結合、接触の判定、1 分単位への分解 |
| `MART` | 提供用 | 指標の算出。可視化やエージェントが参照する |

## 7. ハンズオンで扱う指標

| 指標 | 定義 |
|---|---|
| リーチ | ある期間に 1 回以上視聴した共通 ID の数 |
| フリークエンシー | 接触した 1 台あたりの平均接触回数。分母は接触した台数であり、全台数ではない |
| インプレッション | 接触回数の合計（延べの接触回数）。**リーチ × 平均フリークエンシー = インプレッション** の関係にあり、3 つのうち 2 つが決まれば残りが決まる |
| 推計視聴人数 | 番組の視聴世帯数に、1 世帯あたりの想定人数 2.2 を掛けた便宜的な値。このデータには世帯の人数が入っていないため、固定の係数を使っている。実際にはパネル調査などを正解データにして受信機ごとに人数と属性を割り当てる処理で求める |
| チャンネル遷移 | 共通 ID 単位で、直前に見ていたチャンネルから次のチャンネルへの移動 |
